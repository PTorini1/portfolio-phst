# Pedro Torini — Portfolio

Meu portfolio pessoal e espaço para compartilhar minha trajetória como desenvolvedor de software.

Além de apresentar minha experiência profissional, projetos e principais tecnologias, este projeto também possui um **blog técnico**, onde compartilho aprendizados e experiências relacionadas a desenvolvimento de software, arquitetura, cloud e backend.

🌐 **Portfolio:** em breve

---

## Sobre o projeto

Este portfolio foi criado com o objetivo de ter um espaço próprio na web para apresentar meu trabalho de uma forma mais completa do que um currículo tradicional.

Aqui você pode encontrar:

* minha experiência profissional;
* principais habilidades e tecnologias;
* projetos em que trabalhei;
* artigos técnicos;
* experiências com .NET e Azure;
* problemas reais de engenharia de software e como foram solucionados.

A ideia do blog é principalmente documentar **como problemas são investigados e resolvidos na prática**, incluindo decisões técnicas, alternativas consideradas, trade-offs e aprendizados.

---

## 📝 Blog técnico

Uma das principais partes do projeto é o blog.

Pretendo utilizar o espaço para escrever sobre experiências como:

* desenvolvimento de aplicações com C# e .NET;
* APIs e backend;
* Azure;
* mensageria e processamento assíncrono;
* Azure Service Bus;
* Azure Functions;
* SignalR;
* observabilidade;
* SQL Server;
* Redis;
* Docker;
* arquitetura de sistemas;
* troubleshooting e investigação de problemas em produção;
* automação e RPA;
* integração com serviços de IA.

Os artigos serão escritos em **Markdown** e disponibilizados em português e inglês.

Sempre que um artigo for baseado em uma experiência profissional, informações confidenciais ou proprietárias serão omitidas ou anonimizadas.

## 🎯 O que quero construir

Mais do que uma página para listar tecnologias, a ideia é transformar este portfolio em um registro da minha evolução profissional.

Quero utilizar o projeto para compartilhar não apenas **o que eu usei**, mas principalmente **como pensei e resolvi problemas**.

Por exemplo:

> O que aconteceu?

> Como investiguei o problema?

> Quais alternativas considerei?

> Por que escolhi determinada solução?

> Quais foram os trade-offs?

> O que eu faria diferente hoje?

Esse formato também serve como uma forma de documentar conhecimentos que podem ser úteis para outros desenvolvedores enfrentando problemas semelhantes.
